# NBA 토토 도우미

선수별 통계 표(엑셀식), 팀 통계, 그리고 **부상자를 지정했을 때의 예상 스코어·총점·승리 확률**을 보여주는 프로그램입니다.
추가 설치 없이 macOS 기본 Python과 웹 브라우저만 있으면 됩니다.

## 사용법
1. Mac에서 `시작하기.command`를 더블클릭 → 로컬 서버와 화면이 열리고, 전체 통계를 백그라운드에서 갱신합니다.
   갱신 완료 표시가 나오면 **새 통계로 화면 다시 열기**를 누르세요. 자동 부상 조회를 사용하는 동안 터미널을 열어 둡니다.
   다른 환경에서는 `python3 serve.py --open --update`로 실행합니다. `index.html`만 열면 저장된 자료 조회만 가능합니다.
2. **경기 예측** 탭: 왼쪽에서 경기를 고르거나 팀을 직접 선택 → 아래 로스터에서 결장 선수 체크
3. **토토 배당 계산기**: 베트맨 배당을 넣으면 모델 확률 기준 기대값(+/-)을 보여줍니다.
4. **선수 통계 / 팀 통계** 탭: 열 제목 클릭으로 정렬, `엑셀(CSV) 저장` 버튼으로 내보내기.
   `data/선수통계_*.csv` 파일도 업데이트할 때마다 같이 만들어집니다.

## 파일
- `update_data.py` — Basketball-Reference(통계), ESPN(로스터·부상·일정·시장 라인)에서 데이터 수집
- `index.html`, `app.js`, `forecast.js`, `style.css` — 화면과 예측 모델
- `data/` — 받은 데이터 (`cache/`의 일반 통계는 3시간 동안 재사용, `--force`로 강제 새로 받기; 부상 정보는 별도 최신 조회)

예측은 통계 모델 참고용이며 결과를 보장하지 않습니다.

## 핸디캡·언더오버 시나리오 분석

1. 경기를 선택하고 **홈팀 기준 핸디캡**과 **총점 기준점**을 입력합니다. 홈 -3.5는 홈팀이 4점 이상 이겨야 적중하는 방향입니다.
2. 로스터에서 결장을 체크하거나 예상 출전시간을 입력합니다. 입력한 시간은 고정하고, 나머지 선수에게 자동 배분합니다. 빈칸으로 지우면 자동으로 돌아갑니다.
3. 양 팀 합계가 각각 240분이어야 예측합니다. 선수별 최대 시간은 40분이며, 기록 없는 선수도 직접 시간을 지정할 수 있습니다. 이 경우 선수 평가는 모델 사전값을 사용합니다.
4. ‘정상 출전’, ‘20분 제한’, ‘결장’ 등의 이름으로 최대 3개 시나리오를 저장합니다. 표에서 예상 점수차·총점과 기준점 대비 차이를 비교합니다. 저장한 시나리오의 출전·보정 설정은 보존하며 현재 기준점과 모델 설정으로 다시 계산합니다.
5. 정수 기준점은 동점 확률을 별도 표시합니다. 실제 상품의 동점 처리가 원금 환급인지 미적중인지 확인하고 선택하세요. 미확인 상태에서는 기대값을 보류합니다. 정산 선택은 핸디캡·언더오버에 공통 적용됩니다.

시나리오는 브라우저에 경기·데이터 갱신 시점별로 보관합니다. 다른 경기나 새 데이터에는 이전 경기의 결장 설정을 자동 적용하지 않습니다. 초기화는 현재 경기의 결장·출전시간을 되돌리며 저장한 비교 시나리오는 삭제 버튼으로 지웁니다.

데이터 상태 패널은 누락 통계, 중복 ID, 자료 시각을 표시합니다. 기존 첨부 데이터에는 시간대가 없으므로 최신 여부를 확정하지 않습니다. 이후 업데이트는 UTC 시간대를 기록합니다. Dillon Mitchell에게 잘못 연결됐던 Davion Mitchell의 통계는 제거했으며, 불확실한 이름 연결은 추측하지 않습니다.

모델 확률과 기대값은 기본적으로 검증 전 추정값입니다. 아래 조건을 통과한 항목만 경험적 오차 보정을 적용합니다. 정수 점수의 동점 확률은 정규분포의 연속성 보정으로 근사합니다. 정규시간 240분 모델로 연장을 따로 예측하지 않으며, 포지션별 대체·라인업 효과·팀 통계에 이미 반영된 결장의 중복 보정 문제는 후속 검증 대상입니다. 최신 데이터 재수집과 과거 경기 백테스트는 이번 변경 범위에 포함하지 않았습니다.

## 개발 및 검증

추가 앱 의존성 없이 `python3 serve.py --port 8765`로 실행합니다. 일반 정적 파일 서버는 부상 자동 조회 API를 제공하지 않습니다.

- `python3 tests/test_data.py`: 선수 연결과 첨부 데이터 회귀 검사
- `node tests/test_model.js`: 30팀 출전시간 합계·고정 시간·결장 우선 처리·확률 합계·핸디 부호 검사
- `python3 tests/test_browser.py`: Playwright 및 `/usr/bin/chromium`이 설치된 환경에서 입력·저장·새로고침·경기 분리·정산·잘못된 로테이션 UI 검사


## 시즌 초반의 선수 평가

- 이번 시즌 20경기·경기당 평균 15분 이전에는 작년 기록을 중심으로 평가합니다. 두 시즌 기록이 있고 이번 시즌 150분 이상이면 작년 85% / 이번 시즌 15%로 시작하며, 150분 미만이면 이번 시즌 비중을 더 낮춥니다.
- 20경기·평균 15분 이후의 추가 출전시간 또는 누적 600분 초과분에 따라 이번 시즌 비중을 연속적으로 높입니다 (상한 85%). 누적 600분은 평균 15분 미만의 벤치 선수도 계속 평가에 반영하기 위한 대안입니다.
- 작년/이번 시즌 각각의 BPM은 `누적분 / (누적분 + 250)` 신뢰도로 사용하고 나머지는 작년 300분 이상 기록이 있는 같은 포지션(G/F/C) 선수들의 평균으로 보완합니다. 신인·작년 표본 부족을 작년 기록만으로 과신하지 않습니다. 표의 혼합 통계는 시즌 평균을 섞은 값이고, 모델 BPM은 이 신뢰도 보정을 추가 적용합니다.
- 예상 출전시간은 실력 가중치와 분리합니다. 이번 시즌 평균 출전시간을 `출전 경기 / (출전 경기 + 2)` 비중으로 사용하고 남은 부분만 작년을 참고합니다. 최근 5경기 기록은 아직 없으므로 최신 로테이션을 안다고 가정하지 않습니다. 직접 입력한 출전시간이 우선합니다.
- 이 가중치·600분·250분·표본 기준은 검증 전의 초기 설계값이며 최적 비율로 입증된 값이 아닙니다.

## 예측 기록과 확률·기대값 보정

1. 시작 전 일정에서 경기를 고르고 핸디/총점 기준점을 입력한 뒤 **경기 전 예측 기록**을 누릅니다. 경기당 최초 기록만 저장합니다. 시작 후 또는 임의 팀 조합은 저장하지 않습니다.
2. 당시 예측, 기준점, 배당, 적용 확률, 결장·출전시간, 모델 설정 및 자료 시각을 브라우저에 보관합니다. 이후 설정 변경이나 결과 입력으로 당시 예측을 다시 쓰지 않습니다.
3. **예측 기록 · 검증**에서 실제 **4쿼터 종료 점수**를 입력합니다. 연장 포함 점수는 이 모델의 학습 대상이 아닙니다. 결과는 사용자 입력이며 외부 결과와 자동 대조하지 않습니다.
4. 같은 시즌·모델 버전·모델 설정의 기록만 사용합니다. 중복 경기, 경기 시작 후 기록, 미래 결과는 제외합니다. 예측 전에 알 수 있었던 결과만 시간순으로 사용합니다. 과거 경기 예측을 지금 만들어 소급 저장하지 않습니다.
5. 최소 130경기 중 뒤쪽 `max(30, 전체의 20%)`를 검증용으로 남깁니다. 검증 예측의 최초 저장 시각 전에 결과를 입력했던 앞쪽 학습 경기 100개 이상이 필요합니다. 학습 자료로만 평균 오차와 변동폭 후보를 만들고 검증 자료에 다시 맞추지 않습니다.
6. 편향·분산은 `학습 수 / (학습 수 + 100)`으로 기존 모델 쪽에 수축합니다. 오차 표준편차 하한은 점수차 5점 / 총점 8점입니다. 이 값 역시 초기 설계값입니다.
7. 후속 검증에서 정규분포 오차(NLL)가 줄고, 평균 절대오차(MAE)가 나빠지지 않으며, 해당 시장 기준점이 있는 최소 30건에서 승/패/동점 확률의 Brier 점수가 개선된 경우에만 해당 시장에 적용합니다. 핸디캡과 언더오버는 별도로 승인·보류합니다. 조건 미충족 시 원래 확률을 유지합니다.
8. 적용된 확률로 `적중 확률 × 소수 배당 + 환급 확률 − 1`을 계산합니다. 환급 확률은 실제 규칙이 원금 환급인 경우에만 더합니다. 점수 표시와 승패 계산은 원모델로 유지하고 핸디/언더오버 확률·기대값에만 경험적 보정을 적용합니다.

실제 기록은 처음에는 0건입니다. 테스트용 합성 기록은 사용자 데이터에 들어가지 않습니다. 위 검증 통과는 별도 표본에서의 제한적인 개선이지 이후 경기 성능이나 수익의 보장은 아닙니다. 현재는 평균 오차·변동폭 보정이며, 별도의 로지스틱/등장회귀 확률 보정이나 대규모 과거 실경기 백테스트를 수행한 것은 아닙니다.

기록은 같은 브라우저·접속 주소에서만 유지됩니다. **기록 백업(JSON)**으로 보관하고 **백업 불러오기**로 복원할 수 있습니다. 중복 경기는 기존 기록을 유지하며 브라우저 저장 실패는 화면에 표시합니다. 최대 2,000경기를 보관하고 화면에는 최근 100건을 표시합니다.

추가 검증 명령:

- `node tests/test_forecast.js`: 시즌 가중치, 소표본/벤치 선수, 시간순 검증·미래 결과 제외·모델 설정 분리·정산 계산
- `python3 tests/test_history_browser.py`: 경기 전 불변 기록, 결과 입력, 백업, 합성 자료로 보정 UI 적용과 설정 변경 후 분리 확인


## ESPN 부상 정보 주기 갱신

- `시작하기.command` 또는 `python3 serve.py --open`으로 로컬 서버를 실행하면, 브라우저가 표시되는 동안 5분마다 ESPN 부상 API를 조회합니다. 푸시 방식 실시간 중계는 아니며 ESPN의 원문 갱신 지연이 있을 수 있습니다.
- **지금 조회**로 수동 갱신할 수 있습니다. 여러 탭/연속 클릭도 서버 전체에서 최소 60초 간격으로 제한합니다. 자동 조회 체크를 해제하면 주기 조회를 멈춥니다.
- 마지막 조회 성공 시각과 ESPN 원문 자료 시각을 따로 표시합니다. 원문 시각이 30분 이상 지난 경우 이를 표시합니다. 선수의 개별 부상 보고 날짜는 상태에 마우스를 올려 확인합니다.
- HTTP 오류, 빈 응답, 파싱 실패, 이전보다 오래된 자료는 기존 정상 자료를 덮어쓰지 않습니다. 실패 상태와 마지막 성공 시각을 표시합니다. 명단에 없다는 것은 출전 확정이라는 뜻이 아닙니다.
- 수동 출전/결장 설정은 유지합니다. 새로 저장하는 시나리오는 당시 적용된 결장 상태를 고정하며, 예측 기록에는 사용한 부상 자료 시각을 함께 저장합니다.
- 라이브 부상 자료는 로컬 `data/injuries_live.json`에 보관합니다 (Git 제외). 원래 `nba_data.js`의 팀/선수 통계를 바꾸지 않고 화면에서 부상 정보만 갱신합니다. 전체 갱신 스크립트 역시 부상 정보에 3시간 캐시를 사용하지 않습니다.
- 전체 통계는 시작 시 한 번 갱신하며 자동으로 화면을 재시작하지 않습니다. 실패하면 기존 통계로 계속 사용할 수 있고 오류 상태를 표시합니다. 이미 서버가 실행 중이면 기존 화면을 열며 전체 업데이트를 중복 실행하지 않습니다.
- 예전 `index.html` 직접 실행에서 저장한 예측 기록은 접속 주소가 달라 자동 이동되지 않습니다. 이전 화면에서 JSON으로 백업한 뒤 새 서버 화면에서 불러오세요.

검증: `python3 tests/test_injury_feed.py`와 `python3 tests/test_live_browser.py`. 첨부된 ESPN 원본의 86개 부상 항목 파싱과 로컬 모의 응답 테스트는 통과했습니다. 클라우드에서 ESPN·베트맨의 실제 요청은 네트워크 허용 설정 미반영으로 차단되어 실사이트 연동 성공은 아직 확인하지 못했습니다. 베트맨 기준점/배당 자동 연동은 아직 추가하지 않았습니다.
